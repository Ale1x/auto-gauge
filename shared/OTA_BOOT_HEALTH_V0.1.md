# Durable OTA boot state and local health

Development contract,24October2026. No eFuse/hardware antirollback or resistance to physical NVS tampering. A persistent accepted-release floor gates package admission; it is not a cryptographic monotonic hardware counter. The code is not invoked by the study main.

A single96byte versioned record contains generation, acceptedfloor, optional pendingcounter/targetaddress/imagebytes/SHA256, phase and health-witness mask, plus reservedzero bytes and CRC32. Namespace/floor provisioning is explicit local maintenance, never automatic open/recovery and never a wire command. A blank or corrupt store cannot silently become floorzero. Callback writes must atomically replace one blob; false can follow a committed write. Core always checks exact readback on successful write and becomes terminal UNKNOWN on any ambiguous result until a fresh open/reconcile. No retry/erase/default repair.

Before select the production adapter now REQUIRES a trusted local prepare_selection callback: NULL always refuses selection. The NVS-backed implementation stages the cryptographically verified counter/target/hash, rehashes the actual inactive image, persists intent and reads it back before SDKselect. The installer still performs its own current authorization, partition and bytehash checks. Failure after staging can leave an intent without selecting; no floor advances.

A trial running image must match pendingaddress, bytecount and digest and the boot selection must match running. Local health evidence includes config access, log access, CAN failclosed guard and runtimeclock (mandatorybits0…3), with additional platform checks in bits4…7. A product profile must choose/qualify requiredchecks; this development mechanism does not invent quantitative display/heap/IGN criteria. Evidence is a trusted local mask, never accepted from a phone. Persist a fresh health-witness mask before SDKmark-valid. Only confirmed SDKVALID plus matching durable witness/digest/target allows acceptedfloor advance. A newly stricter requiredmask cannot reuse insufficient old evidence.

If mark-valid reports an error after changing SDKstate, the owner stops UNKNOWN. Fresh startup observes the actual state: matching VALID+durable witness can finish the floor transaction without repeating mark-valid. If SDK falls back to the prior validimage and boot==running, clear the pending intent without advancing the floor. If oldimage still runs while boot points to pendingtarget, report awaitingreboot without mutating state. Unexpected VALID without health witness, wrongimage/digest, unknownstate, failedreadback or corruptrecord failclosed. A pendingimage must gather current localhealth again; a previous partialattempt does not bypass it.

PinnedSDK NVS blob replacement can commit a new BLOB_IDX before failing removal of an older value, and nvs_commit is not a standalone newtransaction boundary in this implementation. Thus false-aftercommit is modeled explicitly. The adapter creates namespace metadata only in a separate explicitprovision call; ordinarybind checks existing namespace READONLY before opening the retained writablehandle under an exclusive namespacewriter contract. No NVS erase or initialization is hidden in bind.

The NVS adapter reads actual partitionbytes with PSA SHA256 and calls esp_ota_mark_app_valid_cancel_rollback. Host shim tests are explicitly noncryptographic/behavioral; realSDK crosslink and prior realcrypto evidence are separate. The installer and boot state now provide an explicit local `allow_factory_bootstrap` profile, defaultfalse: registered nonoverlapping factory→OTA0, trusted baseline provisioning and factory fallback without advancing the floor. No remote flag enables it. Actual platform startup/health collection and hardwarefault qualification remain separate integration work. No physicalflash, mark-valid, reboot or rollback was executed by these tests.
