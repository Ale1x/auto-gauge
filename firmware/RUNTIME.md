# FW11 autonomous host runtime coordinator

`ag_runtime.h` / `runtime.c` connect the existing Service 01 scheduler, measurement quality and a bounded producer queue to synchronous storage callbacks. This is host/simulated integration, compilable for ESP32-S3, with no physical CAN send, GPIO, flash initialization, BLE/cloud dependency or startup from `app_main`. No code grants hardware qualification or infers IGN from CAN traffic.

## Lifecycle and authority

`ag_runtime_init` takes an already selected configuration, discovered ECU capabilities/profile jobs, a fresh trusted nonzero 128-bit SID and storage callbacks. It validates the configuration and requires every configured PID to have an implemented, advertised polling job. Each job must belong to the configuration and pass the existing scheduler's profile/capability, duplicate, timing and shared-bus checks. This does not discover or certify a car. The configuration revision must already have been restored/accepted under the separate durable configuration contract; init itself does not persist or authorize configuration.

Initialization is for an uninitialized or explicitly quiesced instance: it clears RAM. Callers must not reinitialize a running instance or silently discard queued history to reconfigure. Reconfiguration/reboot requires stopping external handoffs, an explicit queue-loss policy, a fresh SID, init and start. SIDs must not come from reset time; freshness is the trusted boot adapter's responsibility.

`ag_runtime_start` establishes the session once through `sink.begin`; any failure, including BUSY, latches terminal fault. It never blindly repeats a possibly committed session start. The supplied journal adapter calls `ag_journal_begin_session`, preserving older retained SIDs. It does not format/bootstrap blank flash; a medium must have been explicitly provisioned/bootstrapped outside this module. No production partition table or 2 MiB region is allocated here.

Every tick/prepare/dispatch/receive/FC call supplies the current trusted `ag_can_policy_t` and fresh monotonic session milliseconds. The existing scheduler checks the complete policy and rechecks it at each host dispatch. USB-only, IGN unknown/OFF, standby, unqualified hardware/rails, bus-off and inactive diagnostic session cannot produce a request/FC handoff. A prepared request does not authorize a later handoff after revocation. Request builders remain fixed to Service 01; FC is transport control and receives the same guard. Output is a simulated handoff, not evidence of physical completion. A future adapter must serialize check/use with policy changes, reconfirm guards immediately at physical send, handle TX failure and reject stale boot callbacks before calling this runtime. CAN/ISO-TP has no authenticated RPC lease; a same-ECU delayed response cannot be authenticated by this host coordinator.

One owner task/lock serializes all calls and synchronous callbacks; no reentry or ISR use. Sink callbacks may block for a bounded adapter-defined time, so the caller must obtain a **fresh clock value after I/O**, not recycle a pre-commit timestamp. Clock regression or scheduler counter/time overflow latches runtime fault; no further TX handoff or storage attempt follows. Existing underlying scheduler state is diagnostic after fault, not authorization to bypass the runtime.

## Measurement and logging semantics

The scheduler retains live values, raw payload, PID, ECU provenance and status. Runtime observes changes in status, update timestamp, raw content, value presence and NRC, then queues a shared history record. Valid records carry the decoder's raw bytes (currently <=8); invalid quality records carry no raw value. Timeout, stale, error and unavailable remain distinct.

This is **observable sample/quality delta logging**, not a transaction audit. An unchanged valid sample on a repeated tick/callback does not log again. Identical repeated timeout/unavailable states with no changed timestamp likewise do not create new records for every failed transaction. Initial unavailable state does not create a fabricated acquisition. NRC remains live measurement metadata; the current shared history record has no NRC field. Deliberate rate suppression is counted separately from producer loss.

The approved rate bound is enforced **globally per PID across ECUs**: at most one producer admission per PID in any 1000 ms interval. Both ECUs may update live, but the first observed eligible event consumes that PID's budget; another ECU/event is suppressed and increments `rate_limited`. At equal observation time, scheduler job order decides. No fair/complete recording of every ECU is promised. Records preserve whichever ECU produced the admitted event. A suppressed change is not deferred or replayed as a new sample when the budget expires.

The queue has exactly 16 records, no heap and no overwrite of its head. If full, the newest eligible event is dropped and `producer_dropped` increments; it still consumes the rate budget. This counter is distinct from journal `evicted_samples`, which counts previously committed samples overwritten by storage rollover. Producer counters are runtime RAM diagnostics, not persistent gap records or an exact crash-surviving acquisition audit. Sequence numbers are assigned only by the storage backend; queued records have sequence zero and are not presented as committed history. Producer losses are not fabricated as journal sequence gaps.

`ag_runtime_drain` attempts at most one head append. `BUSY` is permitted only if the callback guarantees **no mutation**; the unchanged head can be retried later. Success removes exactly one record and increments `persisted`. Any other failure latches terminal fault and leaves the queue for diagnosis; `AMBIGUOUS` explicitly means the backend may have committed. There is no retry or sequence rollback after ambiguity, including lost final confirmation. Restore/reconciliation belongs to a new explicit boot/recovery path. Counters never wrap; impending overflow faults closed. Journal I/O errors map conservatively to ambiguous; other journal failures are terminal. ACKs are not part of this producer and never reclaim history for a phone.

## Bounds and verification

The tested host `ag_runtime_t` occupies 4216 bytes (15 jobs/observed series and 16 queued records); ABI size is not a target stack guarantee. The journal is a separate caller-owned object and can perform substantial scan work; see `JOURNAL_HISTORY.md`. Runtime does not turn its synchronous callbacks into a timing, sleep-current or endurance qualification. Scheduler receive uses its existing bounded ISO-TP stack buffer; integration must measure task stack and execution time before hardware activation.

Six host ASan/UBSan test groups cover invalid/missing configuration coverage and capabilities, explicit session-start failure, repeated events/ticks, global same-PID/two-ECU rate, raw/status provenance, stale/unavailable/timeout, policy revocation between request/FC prepare and dispatch, monotonic regression, queue saturation/BUSY/drop-newest, counter exhaustion, committed-but-ambiguous append with no retry, and actual simulated-journal persistence across fresh boot sessions. No physical device, radio or vehicle is involved.

## Explicit live-only recovery policy

`ag_runtime_allow_degraded_logging` may be enabled locally before start. A failed/ambiguous begin or append then permanently disables logging for that runtime and preserves live polling/quality; no begin/append retry, repair or fabricated durable sequence occurs. `logging_disabled`, `storage_ambiguous` and volatile `not_recorded` diagnostics remain explicit. An ambiguous append may already exist in the archive: not_recorded is an observation of missing confirmation, not a persisted loss range. The original strict default remains terminal on storage failure. CAN/policy/clock/runtime faults are still fail-closed in either mode. This permits a gauge to keep displaying live measurements while storage needs maintenance, without claiming that samples were recorded.
