## Baseline and acceptance oracle

Read `ag_history.h/history.c`, `ag_flash_history.h/flash_history.c`, its simulator/tests, `FLASH_HISTORY_MODEL.md` and `shared/LOG_SYNC_V0.1.md`. The existing two-bank COW store is a recovery reference, explicitly not a production append log. Its conservative READ_ONLY behavior on a dirty competing bank must not be silently weakened into an assertion that a damaged/newer sector never existed.

The journal must preserve these externally meaningful properties:

- A committed record has a stable (device, SID, sequence) identity and canonical contents; retry cannot silently replace it with another sample. Sequence and global serial never wrap. A fresh boot needs an explicitly fresh trusted SID; opening media never resumes old monotonic time implicitly.
- Record order and reported loss are exact for the requested SID and cursor. Fully evicted/unprovable sessions are not returned as complete empty pages. Incomplete append does not establish that a never-committed sample existed. Loss caused by reclaiming committed data is distinct from producer/RAM overflow.
- ACK from A does not erase data needed by B and does not create an unbounded device-side cursor table. Page output and errors must retain the established bounded wire semantics, raw64/status validation and uint64 decimal precision.
- Startup never auto-formats corrupt or unreadable media. Short reads are errors, not erased bytes. A successful append means its record/marker has been checked through the defined synchronous durability/readback contract. An interrupted operation can be durably committed before the caller observes success; recovery determines the authoritative result.

## Risk-driven fault-injection plan

1. **First append / ordinary append / last slot.** Cut every programmed byte, including headers, record body, CRC and commit marker; cut reads at0/1/length−1 and inject final readback failure. Recovery must return a canonical committed prefix or an explicit error, never malformed record success. Repeat append after reopening according to session policy.
2. **Rollover and reclaim.** Start with distinguishable data across at least three sectors, include a sector boundary inside a session, then cut each erase/header/marker/program step when reclaiming the oldest sector. Verify unaffected sector bytes remain unchanged. Committed eviction intent can define LOGICAL eviction before physical erase; the on-media format and query policy must explicitly use that commit point consistently, regardless of whether residual bytes remain. A partial/uncommitted intent cannot authorize erase or hide retained records. Repeated failures must not erase multiple valid sectors through restart guesses.
3. **Session transition.** Cut begin-session metadata and the first sample of a new SID. Old-session pages remain valid; new boot/session distinction is retained even if the new session is empty. Reused retained/current SID must fail. Freshness beyond retention remains a caller obligation.
4. **Selection and corruption.** Flip every byte of a newest sector/header/record including padding, then test duplicate generations, conflicting same-generation contents, missing sectors, reversed age/index and valid-CRC semantic counter regressions. Never silently choose a convenient older state while claiming complete synchronization. CRC protects accidental corruption, not hostile forgery.
5. **Sequence/geometry arithmetic.** Exercise capacity1/minimum geometry, nonmultiple/oversized geometry, overflow-prone offsets, UINT64_MAX sequence/serial/generation exactly once, clock regression, invalid PID/ECU/status/raw0/64/65 and output capacity0/exact/short. Detect all out-of-bounds IO with the simulator and ASan/UBSan.
6. **Client/query behavior.** Compare pages before/after ACK for two independent cursors and multiple sessions; exercise cursor ahead, fully evicted SID, empty current session, overwritten prefix, raw64/u64max budget and conservative degraded-media results. Compare shared golden pages with the existing RAM/COW producer when semantics overlap.
7. **Cost and operational boundary.** Count program/erase/read calls for non-rollover append and rollover separately, including scans/readback. Verify writes do not copy all retained data per append. Report bounded memory and nested stack, capacity/retention cost and wear amplification using the actual development format; do not assert a physical endurance, throughput5Hz, OTA fit or partition size from RAM simulation.

## Final format and findings

No unresolved concrete P0/P1 defect was identified in the reviewed final source under the serialized trusted-IO contract. This is not a production activation gate.

Before freeze, the firmware owner identified an actual recovery ambiguity: an entire ACKed last entry or newest header becoming0xff could resemble an unused tail, permitting silent rollback. The corrected format reserves an entry with duplicated monotone bitmaps at header112..119 before writing its body/marker. Header static CRC covers0..111; the independent scan rejects duplicate mismatch, noncanonical bit pattern or reservation count different from canonical committed entries. A reserved but absent entry produces READ_ONLY rather than a reused sequence.

Rollover additionally sets duplicated creation witnesses in the predecessor's committed footer before creating the next header. Static footer CRC excludes mutable witness88..95 and binds the intended victim, successor/index/geometry, sample eviction and canonical prior session state. Witness mismatch is degraded. A latest footer with a creation witness but missing/invalid successor cannot recreate a convenient empty header. Static intent remains recognized for logical eviction even when its witness is torn, so an ambiguous creation cannot resurrect already-evicted samples. Entire-media loss remains indistinguishable from never-used blank storage; bootstrap is explicit and fresh trusted SID remains mandatory.

The closing review verified bitmap/witness ordering in source and reproduced the ACKed-loss cases below. Partial entry/metadata writes conservatively disable operational pages and writes. This may halt logging after interruption and requires a separate explicit recovery policy; the review does not reinterpret READ_ONLY as successful autonomous recovery.

## Limits and next boundary

At512sectors the format has15360entry slots (2MiB H), including controls, rather than a promise of seven hours. With only samples at5Hz, the upper slot-count duration is3072seconds/51min12s; actual session controls and whole-sector reclaim reduce it. This is format arithmetic, not a frozen partition/retention decision. The observed host store metadata size is5776bytes, fixed by512-sector arrays. No heap or whole-log recopy is used.

A non-rollover append scans the current sector, reserves8bitmap bytes and writes128entry bytes in four program calls with no erase; rollover adds intent/header/witness and at most one victim erase. These are callback-level model costs, not flash endurance/latency or electrical measurements. Repeated partial programming of bitmap/witness words, flash encryption alignment, erase behavior and real power interruption must be qualified for the selected component/driver. Wear-level lifetime and sustained5Hz remain unproven.

`ag_journal_make_page()` and `ag_journal_window()` have nested fixed-size snapshots (each6200bytes on this host), plus helper and serializer stack. The default app_main stack is not qualified; actual target high-water/latency/stack and owner scheduling must be measured before runtime integration. Trusted fresh boot/SID generation, provisioning, physical flash IO/partition, OTA sizing and the approved logger's≤1Hz/PID ingestion policy are separate work. CRC and monotone reservations detect the modeled accidental faults; they are not authenticated storage or proof against correlated arbitrary rewriting. Session freshness beyond fully evicted history remains caller responsibility. These tests do not supply a physical backend, radio connection or automatic repair of degraded media.

## Follow-up: typed journal-to-endpoint adapter

Read `ag_journal_endpoint.h`, `journal_endpoint.c` and `test_journal_endpoint.c`. No concrete defect identified in the intended typed `options.history_read` use. The adapter clears the caller snapshot before any read, maps journal OK/READ_ONLY/NOT_RETAINED/CURSOR_AHEAD explicitly, and maps other failures to UNAVAILABLE. It does not turn unknown/evicted SID into a misleading complete empty page. Null context/output cannot produce success. `ag_journal_window()` assigns its candidate only on success, so an error cannot resurrect a prior client's snapshot. Normal query may poison a corrupt store's in-memory readiness; that is conservative state invalidation, not a flash repair/write.

Independently compiled actual adapter/journal/history and existing flash simulator with C11 warnings as errors, ASan and UBSan in a temporary directory; `test_journal_endpoint.c` passes. Checks cover retained window16, exact loss1..30, tail page and cursor completion, cursor-ahead, unknown SID, querying after reopen without writer attachment, old/new session coexistence, short-read failure, corruption→READ_ONLY, output clearing and zero program/erase calls from read queries. No production source, CMake/shared build or hardware was modified. This validates the callback boundary, not a radio roundtrip or physical persistence.
