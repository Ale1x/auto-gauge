# NimBLE compile study — independent review

Date: 2026-10-24. Status: SOURCE_REVIEWED_COMPILE_STUDY; NOT_RADIO_VALIDATED.

Scope: `firmware/ble_study/main/nimble_transport.{h,c}`, defaults, build script, linker retention and `scripts/generate_gatt_header.py`. Read-only review of implementation; only this report was written. No flash, NVS initialization, radio start, second SDK build or vehicle operation was performed.

## Findings and corrections

Two P1 lifecycle defects were identified in the initial revision and corrected by the coordinator during review:

1. **Failed termination could wedge the singleton indefinitely.** The original close path ignored `ble_gap_terminate()` and stopped servicing closing links. SDK `ble_gap.c` confirms failures can return without a disconnect event. The revised `try_terminate()` services closing links from the timer, completes local cleanup when the descriptor is absent, retries errors at most three times, and emits a latched termination fault. Successful termination waits for the real event, with a 30 s deadline rather than repeated terminate commands. A controller failure can still require reboot; this is now an explicit fail-closed state rather than silent recovery or false disconnection.
2. **Host-task allocation failure could falsely return startup success.** In this SDK, the FreeRTOS wrapper is void and its underlying `esp_nimble_enable()` ignores `xTaskCreatePinnedToCore()` failure. The revised startup owns the task and checks `pdPASS`; failure stops/deinitializes the initialized callout, faults the singleton, attempts SDK cleanup and returns `ESP_ERR_NO_MEM`. A failed SDK cleanup cannot authorize retry because the fault remains latched. Partial initialization is not claimed recoverable.

The follow-up review also identified ignored timer-reset and asynchronous address-initialization errors. The revised `arm_timer()` faults, closes any link and stops advertising if reset fails. Both address setup failures in `synced()` now signal `AG_NIMBLE_FAULT_START`. Unexpected host-loop exit faults before clearing `started`, stops the timer, and deletes the owned task; the fault prevents restart over retained SDK state. Callback context must remain valid even after failed startup, as documented in the header.

No additional concrete P0/P1 defect was identified in the final source under its documented serialized-owner and trusted-callback contract. This is not a production acceptance verdict.

## Security and transport observations

- RX and every outgoing indication chunk independently require the current connection generation, encryption, authenticated pairing, bonded SC keys, matching resolved identity, 16-byte live/stored keys, and the trusted admission hook. The helper deliberately does not manufacture evidence that the current displayed passkey was used. Admission, boot identity and journal authority remain caller responsibilities.
- SC-only/MITM settings, disabled debug keys and disabled automatic repeat-pairing deletion are consistent with the pinned SDK. Repeat pairing closes the current link and returns IGNORE; store pressure faults instead of evicting another client's bond. The configured eight-bond capacity is an implementation bound, not a claim of unlimited retained bonds.
- The request characteristic requires authenticated encrypted writes; response reads fail. Subscription alone cannot bypass the private-output guard. Frames are bounded to 4112 bytes; each chunk is bounded by both MTU−3 and 512 bytes, with one outstanding indication. Status 0 is not treated as acknowledgement: only `BLE_HS_EDONE` advances the frame. Confirmation is ATT delivery, not application persistence.
- Connection callbacks receive an immutable scalar generation through `ble_gap_set_event_cb()`. Stale callbacks are rejected before processing. Generation stops at `UINT32_MAX`, preserving the tag on the 32-bit target without wrapping. Reused connection handles alone cannot authorize stale callbacks.
- Frame/request timing uses absolute monotonic milliseconds. Local hooks must meet their contract: single host-task ownership, static context lifetime, no reentry into start/close/send (except the documented tick→send case), and copying borrowed RX bytes before returning. This review does not establish thread safety for callers outside that contract.

## Follow-up: endpoint binding and bond lookup

Reviewed `endpoint_bridge.{h,c}` and `ag_nimble_lookup_bond()`. The transport checks NVS persistence at compile time; lookup uses the SDK connection's identity address rather than wire identity and requires retained authenticated SC/16-byte LTK evidence. ENOENT alone means unknown, while malformed entries or other storage failures deny admission. The local key-value copy is wiped before return; that statement comes from source review, not an invalid read after stack lifetime.

The bridge maps the current immutable SDK generation to the core boot/lease, uses trusted local UI and RNG hooks for a new peer, and supplies native security evidence to admission. The temporary display flag supports initial verification and is cleared afterwards; subsequent access re-reads SC/MITM/bond/key evidence independently. Unknown peers cannot enter without a local pairing window. Recognized lookup depends on the SDK's identity resolution and retained key store; interoperability with actual private addresses remains a radio test dependency.

The bridge's tick calls the real endpoint once, consumes a complete framed response into bounded storage, and holds `awaiting` until the transport reports final ATT confirmation. This is the critical wiring that delays the endpoint's next apply-commit phase. A send failure disconnects the core and cancels work not already committed; late generation callbacks cannot release the current peer. Fresh clock reads occur after synchronous endpoint/storage IO, so an expired response cannot reuse a pre-commit timestamp. An IO-expired request can nevertheless already be committed; reconnect/readback is the recovery path, not a promise of rollback. Initial connection and store/journal/boot identity/physical persistence provisioning remain explicit external prerequisites.

The extended host suite passes **2 Python tests, 10 transport/lookup groups plus 5 bridge/core groups**, with ASan/UBSan and warnings as errors. Bridge production C is linked separately alongside the actual config, config store, admission, connection, history codec, endpoint, frame, stream, RPC and JSON C. Tests cover unknown denial, local-window→render→SC→hello, received-ID91 with zero programs before final EDONE and apply/readback afterwards, A→B→A lease isolation, stale callbacks, close/awake denial before commit, failed RNG/render without SMP injection, mandatory platform callbacks, and a 40-second IO delay that blocks stale output despite successful commit. The test uses flash simulation with truthful VOLATILE wire metadata; physical durability is not established. No new concrete production bug was identified under the documented ownership/callback contract. Root's real SDK build remains separate; no SDK/radio action was executed during this follow-up.
